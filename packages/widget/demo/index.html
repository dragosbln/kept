The launcher sits bottom-right. By default it talks to a scripted MockTransport; the happy path mirrors the demo backend's order-1001 / dana@example.com (say hi, then send both to get "verified" and a tracking link).

To point it at a running agent service instead, add ?endpoint=http://localhost:3100 to this page's URL.

Force a failure (mock only)

/fail turn fails server-side → message marked not delivered, retryable
/refuse model refusal outcome → same customer-facing failure state
/full conversation_full → composer swaps for "start a new conversation"
/locked HTTP 409 conversation lock → "still being handled" copy
/timeout transport timeout → delivery unconfirmed, not failed
/offline network error → delivery unconfirmed
/garbage unparseable 200 → delivery unconfirmed

failed vs unconfirmed is the point: the widget only claims a message failed when the server is known not to have processed it.
